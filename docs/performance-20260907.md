# 2026-09-07 性能优化说明

## 聊天记录存储迁移

聊天记录改为同目录的 `conversations.sqlite3`。首次启动时只读导入原 `conversations.json`；全部消息和迁移完成标记在同一事务提交，失败不会留下部分导入数据。原 JSON 文件保持原样，不会自动删除或覆盖。

之后每条消息只追加对应会话的一条数据库记录，并在同一事务更新消息数和标题；不再重写所有历史正文。列表只查询标题、日期、消息数，正文按需读取，应用侧最多缓存最近访问的一个会话。一个很长的当前会话仍会占用其自身正文大小的内存，这不是无界历史缓存。

### 备份与回滚

- 请正常退出 LLMChat 并确认后端退出后，再备份 `conversations.sqlite3`。若 `conversations.sqlite3-wal`、`conversations.sqlite3-shm` 仍存在，一并保留；不要在应用运行时仅复制主数据库文件。
- 原 `conversations.json` 是迁移时快照。新版新增消息、改名和删除不会回写原 JSON。
- 直接运行旧版只能看到旧 JSON 快照，看不到升级后的新消息；原数据库仍保留新消息。不要为了回滚直接删除数据库，也不要自行覆盖原 JSON。
- 若必须把新版新增内容带回旧版，应在停机备份后另行执行明确的数据库导出；当前优化未自动执行回滚导出。
- 已迁移成功后再改旧 JSON 不会重新导入，避免复活已删除会话或产生重复记录。
- 原文件格式错误、重复会话 ID 或数据库写入失败会明确报告，原 JSON 保留，迁移事务回滚。

数据库主文件及 SQLite 临时/日志文件已加入 Git 忽略，不能作为源码提交。便携版打包只更新程序文件，不清理这些用户数据。
