# Unity 嵌字翻译首版

入口为左侧「Unity 翻译」。选择或拖入游戏目录 / 主程序并识别游戏后默认进入嵌字翻译，上方可切换运行时翻译，无需额外选择模式页面。游戏标题、模式和一键操作合并在同一栏。

目录检测由本地服务的后台请求线程执行，不锁定最近打开列表。点击最近游戏会取消当前扫描并仅检查该游戏目录；客户端断开后，递归扫描在下一检查点结束，旧结果不再覆盖新选择。不点击时继续检测至完成。启动时读取上次游戏工作目录的任务摘要，未完成的工程自动打开并恢复原步骤，不自动开始翻译或应用；已经开始手动选择时不抢走当前界面。

## 操作

1. 工程、检查点、中间文件、补丁和原件备份统一保存在游戏内的 `LLMChat-Unity` 工作文件夹。任务索引存为工作目录的 `task-state.json`，工作文件路径相对于此文件夹保存。读取进度直接使用游戏工作目录，不依赖软件目录或浏览器缓存。已有软件目录工程在首次进入时复制迁移，旧文件保留；不再提供手动导入入口。游戏目录必须可写，不静默改存到软件目录。
2. 识别并选择游戏后，自动加载对应游戏工作目录中的任务和工程，没有历史工程时使用一键流程。扫描排除 `LLMChat-Unity`，防止重复提取自己的工程和备份。处理游戏数据目录中的 UTF-8 TXT / JSON、Unity TextAsset 和序列化游戏组件；Mono 游戏可从 Managed 程序集读取结构定义，提取对白、选项、名称、描述和 UI 字段，即使资源未内嵌类型树。程序集中仅解析元数据，不执行游戏代码。可选扫描 Mono 代码字面量和版本 24–31 的标准 IL2CPP metadata 字面量。
3. 点击四个步骤标题切换参数：扫描步骤配置原文范围和代码扫描；翻译步骤配置大模型／翻译引擎及目标语言；补丁步骤配置可选字体并显示工作目录；应用步骤显示写入位置和检查要求。各单步按钮仅执行本步，缺少前一步结果时禁用；可提前配置后续步骤。一键处理依次使用全部参数。重新扫描建立新工程并保留旧工程和匹配译文。步骤区与结果区之间，以及表格来源、原文与译文列之间均可拖动分隔线调整宽度；窄窗口自动上下排列。
4. 可选提供具有目标语言字形的静态 TTF / OTF。检查 Unicode cmap 缺字并替换 UGUI FontData；TMP 单图集和 NGUI 独立位图字库原生生成图集与字形数据，无需安装 Unity Editor。
5. 请先关闭游戏。补丁目录中 `patch` 保存修改文件，`original` 保存对应原件，`manifest.json` 记录哈希。一键流程最后自动应用，也可在生成后单独点击「应用到游戏」。应用前检查游戏进程、原文件及补丁哈希，逐文件原子替换并校验，写入失败时回滚；原件备份始终保留，可按相对路径复制回游戏恢复。

## 进度、中止与恢复

翻译步骤的“断行方式”默认使用本地智能：系统分词、标点禁则、数字单位保护和相对宽度估算共同选择断点，整体优化各行，不下载模型、不额外请求模型。保留原行数、空行、缩进和换行符，保护格式标记与完整字符；宽度估算尚不等于游戏字体、文本框的实际尺寸。无法合理保留行数时明确报错，可手动排版或选择“原行比例”。

“仅重新断行”处理当前选中的已有多行译文，不请求重新翻译，也不要求配置翻译引擎凭证。断行方式可在已有译文或已应用补丁时调整；未应用的补丁在确认后清理，已应用的补丁在确认后先恢复游戏原件，再清理旧补丁。扫描和译文保留，排版完成后重新生成并应用补丁。每条原有译文独立保留文字，重复原文的不同人工译文不会被合并覆盖。任务保存“仅排版”标记，中止或重启后恢复断行，不转为全量翻译。

翻译步骤分别提供“重做翻译”和“重做断行／仅重新断行”，不使用含义模糊的“重做此步”。前者确认后清除译文与后续产物；后者仅清理失效补丁，排版成功前保留原译文，失败或中止也不清空原译文。

大模型辅助是主动选择的次选方案，仅多行文本增加请求，可能产生 API 费用或占用本机模型资源。复用通用设置中的连接，模型只能从合法候选位置返回断点，不能改写文字；无效输出不会自动重试或切换到付费模型。重复原文复用断行结果。译文先保存为排版草稿，排版失败或中止后恢复时复用草稿，不重新请求已完成的翻译。暂停在翻译步骤时允许切换断行方式或辅助模型，不清除已有译文；人工修改的有效译文继续保留。

四个步骤均显示当前操作、已处理数量和本步进度，单条进度条平滑过渡，处理中有左到右的流光。列目录或校验时尚无准确总量，显示准备状态，不编造百分比；失败、中止及完成后停止流光。单独执行步骤和一键流程均可「中止」「恢复」，资源操作在当前文件安全处理完后停止。失败原因和处理建议直接显示，原始错误折叠在技术详情中。

步骤标题不重复显示状态文字：完成步骤淡绿、当前步骤淡蓝、尚未执行步骤淡橙，选中参数页显示对应的深色；查看参数不改变任务进度。未知总量时填充从 0 开始，只有流光表示正在处理。说明、授权、制作名单、引擎构建信息和运行时标识不作为游戏原文；旧提取方式建立的工程会提示重新扫描，一键流程自动重新提取并保留匹配译文。

翻译前用第一条实际待翻译文本检查服务可用性，成功结果直接保存复用，不额外发送重复测试文本。预检失败不启动批量；处理中连续 3 次或累计 5 次请求失败，保存已完成译文后自动停止并显示原因。文件保存失败立即停止，不将其当作服务请求失败继续处理。列表错误收为紧凑详情入口，不再把每行撑高。

大模型翻译可跟随通用当前模型，也可在翻译步骤选择通用中已配置的其他模型，包括本地模型。连接地址和凭证仍从通用读取，不写入游戏工程；任务仅保存所选模型标识。本机模型服务须先启动，可不填 Key。查看后续步骤时显示该步参数，不显示其他步骤的进度条；正在执行的任务另有紧凑的中止、恢复和查看进度入口。每步成功完成后切到下一步参数页，最后一步留在本页；单步操作只切页，不自动启动下一步。重做按钮以黄色显示，清理完成后仍由用户手动启动。

同一原文在本轮只请求一次，包括失败条目；换行格式、Unicode 组合形式和首尾空白归一后去重，原资源位置与首尾空白保留，译文传播到所有待处理引用。已有有效人工译文保留并可复用。进度同时显示条目数量和去重后的原文种类。

翻译步骤的“换行处理”默认“合并翻译后恢复换行”：先取消实际换行，将整条文本发送给引擎或模型，再按原文各行长度比例恢复行数、空行及 LF/CRLF 等换行符格式，优先在词间或标点处换行，不拆开占位符、富文本标签或组合字符。中日文相邻文字直接连接，其他文字间保留空格；程序转义保持不变。译文长度会变化，断行不是原文字符位置的机械复制，游戏中仍需核对显示。原文不改写，也可选择“保留换行翻译”。选项随任务保存，恢复使用原选项；已有译文不会自动覆盖，需要重新翻译时可重做翻译步骤。

翻译主进度按已完成的唯一原文种类计算，另列资源位置覆盖数、本轮请求数和复用种类；重复文本不会把一次请求伪装成大量独立翻译。结果分页可跳转指定页，或前后移动十页。

类型、程序集、方法及 Unity 事件绑定标识不属于游戏文字。扫描时排除，旧工程载入和保存时剔除误收条目，保留正常译文和资源位置；生成补丁再次检查，旧规则生成且缺少保护校验的补丁禁止应用，须重新生成。保留原件备份用于恢复已应用的旧补丁，不把错误的类型标识译文写回游戏。

翻译中止后可继续，或选择“跳过剩余并生成补丁”，仅回写已完成且校验有效的所选译文，其余保持原文；这个选择随检查点保存，不自动应用游戏。完成步骤可“重做此步”：先校验并恢复已应用的游戏原件，再清除本步及后续产物，随后调整参数重新开始。重做应用也会删除旧补丁，需要重新生成。清理过程有独立检查点，异常中断后打开游戏工作目录会先完成已授权的清理；游戏文件被其他程序修改时停止并保留备份。

步骤失败显示淡红，选中为红色；查看其他参数页时，正在执行的步骤用呼吸效果强调。步骤区与输出区可拖动调整高度，输出区填满剩余空间，工作目录位于顶端。读取到对象数据末尾的提示按类别汇总，显示受影响对象及未提取文本/字体的影响，不能仅凭这类提示认定游戏损坏。

## 多语言文本范围

游戏资源可能同时保存日文、英文、韩文等字符串。工程保留完整提取结果；默认按数量最多的主语言显示，原文语言可手动指定或选择「全部语言」。列表、翻译选取、补丁回写和字体缺字检查均使用同一语言范围，不会把未翻译的其他语言混入补丁。未带语言标签的文本按文字特征判断，纯汉字可能同时用于中文和日文，因此不强制删除。切换语言不会删除原文、译文或手动选取。

- 扫描按文件保存工程和扫描位置；恢复继续剩余文件。翻译逐条保存，恢复跳过有效译文，不重复请求已完成文本。
- 补丁生成保存已完成文件和原件备份，恢复校验后继续，不重复生成已完成文件；译文或字体改变时不能混用旧检查点。
- 应用记录完成文件并校验哈希，恢复跳过已写入文件；中止或意外退出可能留下部分已应用文件，应用完成前请勿启动游戏。写入失败会尝试回滚，若回滚失败会列出需从 `original` 恢复的文件。
- 重新选择当前游戏时读取本机保存的任务索引，加载工程并显示恢复入口，不自动继续联网翻译或写入游戏。任务索引不保存密钥，检查点和工程保存在输出目录。处理中退出会先中止并保存，再关闭窗口。
- 「结束本次流程」保留工程、译文和补丁，但不再自动继续；应用中止后必须恢复完成，不能直接结束以免误把部分应用当作完成。支持范围和实际游戏显示限制不因一键操作而改变。

## 运行时模型与引擎

运行时可使用插件自带引擎，也可点击「使用 LLMChat 大模型翻译」启用已有 CustomTranslate 本地桥接。桥接直接读取通用的当前模型、API 和密钥，游戏配置只写入本地桥接地址，不写入大模型密钥；使用期间需保持 LLMChat 运行。

插件自带引擎的参数写入 AutoTranslator 自己的 Config.ini，与通用翻译引擎接口不是同一条调用链，因此仍在 Unity 设置中维护。嵌字模式不安装运行时插件。

## 已实现的检查与限制

- 扫描步骤可选择按段落或按行提取文本；段落保留内部换行，跨行上下文不会在扫描时被提前拆散。新工程使用扫描规则 3，旧工程保留，重新扫描会按完整来源和原文匹配已有译文。
- 代码扫描默认关闭。启用后列出游戏 Managed 中可回写的程序集，独立翻译 DLL 也可选择；引擎程序集不进入这个列表，已签名或无法读取的程序集显示原因并禁用。
- 可选择 Managed / DummyDll 类型定义目录。定义复制到当前游戏工程中并记录哈希，恢复和生成前校验；只读取元数据，不执行 DLL。
- 文本处理和字体生成无需 Unity Editor。Windows 原生字形生成使用所选静态 TTF / OTF 私有加载，验证实际选中字体，禁止系统字体回退；当前覆盖 BMP 字符。TMP 支持 `m_GlyphTable` / `m_CharacterTable` 的单图集布局，生成 SDF 或位图、更新字形度量与材质参数并保留对象引用；NGUI 支持独立 BMFont 位图和字形回写。生成过程中检查中止，恢复时保留已完成资源文件。
- TXT、JSON、CSV、TSV、XML 按对应结构提取与回写。CSV 仅处理可识别的正文或语言列，保留键、表头及其他列；引号内换行属于同一字段。XML 保留结构，禁用 DTD；JSON 和 XML 的语言字段优先于文字脚本猜测，法语与英语不因同为拉丁字母而混在同一范围。
- 输出区显示可读取、无目标、部分解析和失败的资源数量。失败对象保留资源位置、具体原因及处理建议，不将流结束异常直接解释成游戏损坏，也不将部分解析显示为全部成功。
- 补丁步骤可生成 `font-plan/characters.txt`、字库检查和字体依赖清单。实际字符集包含有效译文、未翻译原文、英文数字及用户补充字符；区分源字体缺字和 TMP / NGUI 所需条件。重做翻译或补丁会清理这部分生成产物。
- 写回临时补丁后重新打开 DLL、metadata、文本或资源文件，对照原定位检查译文；UGUI 替换后检查字体字节和原有引用，TMP / NGUI 对字库、纹理和材质对象逐一比较序列化数据。重读通过才记录完整补丁，校验失败保留未完成标记，不能应用。

- 校验占位符、转义和富文本标签集合，并保持标签嵌套、转义及非定位格式参数的顺序；带编号的格式参数允许正常调序。空译文或缺字阻止生成。检查源文件哈希，源文件变化时要求重新扫描。
- 自定义二进制、图片文字和加密资源不自动解析；无法识别的 CSV 表头不作为正文列，特殊脚本需要单独适配。
- 字面量中可能包含影响程序运行的标识，因此代码扫描默认关闭；启用后必须检查选取结果。已签名 Mono 程序集不自动回写。
- 支持序列化 assets 以及可读取的 Unity Bundle 回写。修改 Bundle 不自动更新 Addressables Catalog / CRC，不保证游戏允许加载；扫描提示会列出已检测的 Catalog。
- 缺少 Managed 程序集或结构解析失败的自定义组件会显示跳过原因。旧版 TMP 布局、多图集、跨文件字库引用、NGUI 共享 UIAtlas / 图标符号和动态／引用字库尚不自动回写，生成时明确报出资源位置，不覆盖共享图片。特殊 shader 与运行时动态文本仍需适配；类型数据库覆盖不到的引擎版本会显示错误。通过重读校验不等于通过游戏实际显示验证。
- 补丁生成失败时保留 `INCOMPLETE.txt`，不得使用此目录。游戏加载、排版和字体实际显示仍需用目标游戏验证。
- 翻译通过用户选择的已有模型连接发送；工程与补丁不保存密钥。使用本机模型时不需要将原文发给云端服务。

## 构建

需要 .NET SDK 8 或更新版本。`scripts/prepare-unity-tools.ps1` 发布 Windows x64 自包含组件并下载固定版本、校验 SHA-256 的类型数据库；最终用户无需安装 .NET。

Tauri 的构建前命令自动准备组件，便携打包复制 `resources/unity`。开发时先按仓库全局锁流程运行准备脚本，再启动 Tauri。NuGet 与类型数据库首次下载需要网络；组件准备好以后，扫描和生成补丁不联网。

核心依赖为 AssetsTools.NET 3.0.5、Mono.Cecil 0.11.6；类型数据库来自固定 UABEA 提交。第三方说明随组件放在 `resources/unity`，不分发教程工具包中的旧 EXE 或“特别版”程序。


## 本地多语言断行辅助

“断行方式 → 本地小模型”使用 MIT 许可的 WtP BERT Mini（`benjamin/wtp-bert-mini`，固定版本 `ac9218133a447014fa557a9997a1422def9bc6e8`），支持包括日文、中文、英文在内的 85 种语言。它提供句子边界分数，由现有词语、标点、字宽、段落和列表规则选择合法断点；不翻译或改写文本，不保证游戏内实际布局。不会跨游戏字段合并文字。

模型复用现有 ONNX/WASM，在独立 Worker 按需加载；任务完成或中止时终止 Worker。长文本按 512 个 Unicode 字符窗口、256 步长重叠推理，映射回原始 UTF-16 位置，并过滤字素、标签和占位符内部断点。旧工程的 HanLP 选项恢复为此选项；已有译文保留，需要改变已有排版时使用“仅重新断行”。扫描阶段的模型分段见下文。

`scripts/prepare-unity-segmentation.ps1` 首次准备时下载并校验官方模型，再由 `scripts/convert-unity-wtp.py` 将 FP16 图转换为 FP32（28.20 MiB），兼容现有 WASM 内核；清单和 MIT 许可随模型打包。首次构建需 Python 与 `onnx==1.17.0`，可用 `LLMCHAT_MODEL_PYTHON` 指定解释器，模型准备后构建不再调用 Python，最终用户无需安装 Python，也不调用 API。

参考：<https://github.com/segment-any-text/wtpsplit/blob/main/README_WTP.md>、<https://huggingface.co/benjamin/wtp-bert-mini>。


## 扫描时的智能分段

在“扫描资源 → 文本分段”选择“智能分段（本地小模型）”。扫描组件使用同一个 WtP BERT Mini 模型，通过 CPU ONNX Runtime 本地推理，在每个原始字段内部判断已有换行是否为句子边界；排版折行保留在同一条原文中，空行和列表条目单独分组。不同 Unity 字段、JSON 属性、CSV 单元格、XML 节点或程序集字面量不会相互合并。标签跨行包裹时保持该字段整体，避免拆坏标签。

每段记录原字段位置和完整原文；生成补丁时先验证原文位置，再仅替换选中的片段，保留片段之间的空白与未选择的文字。重读校验比较重建后的完整字段，不对译文再次推断分段。扫描仍按文件保存检查点，中止后从未完成文件继续，模型在扫描进程结束时释放。

智能分段改变扫描条目，已有工程需要明确重新扫描才能采用，不会自动清除译文或改变既有工程。模型辅助并不等于人工语义校对，应检查列表、对白和短标题的分组。扫描格式版本为 4，旧版按行／按段落扫描仍可使用。首次准备模型的规则与断行辅助相同；扫描助手另外携带 CPU ONNX Runtime，无需用户安装 Python 或 .NET。


## 2.1 文本与 2.2 图片

第 2 阶段分为 2.1 翻译文本、2.2 图片识别与翻译，分别保存进度、分别中止／恢复／跳过；跳过保留已有有效结果，未处理内容保持原样。自动流程并行处理两部分，两部分完成或明确跳过后再生成补丁。

扫描收集可解码的 Unity Texture2D 与游戏数据目录内的 PNG/JPEG。2.2 复用图片模块的本地 PaddleOCR，以及可选 Manga OCR；凭证、代理和翻译模型沿用通用设置。只有 OCR 原文会按所选引擎发送翻译，不上传原图。识别结果、坐标和译文保存在游戏工作目录的图片检查点中；重复原文复用有效译文。连续多次失败停止，已有结果可恢复。

译图采用纯色覆盖后嵌字，不重建复杂背景；预览原图与译图，可编辑文字、译文和坐标，或导入同尺寸 PNG 替换译图。PNG 缓存、图像状态及中间文件均位于工程 images 子目录。字库图集、已识别的法线／光照纹理不参加图片翻译；不支持的布局显示原因。

生成补丁保留原纹理的尺寸、对象 ID 和资源引用，译图转为 RGBA32 内嵌像素并清除外部数据引用，资源可能增大。原图使用外部 resS 时校验依赖哈希；修改后重新解码核对像素，再进入已有备份和应用流程。外置 JPEG 采用质量 95 重新编码。Addressables Catalog／CRC 仍需单独验证，实际显示应在目标游戏复测。


## 重新扫描复用与并行任务

“重新扫描资源”先使旧补丁和字库检查失效，必要时恢复游戏原件，保留旧工程中的文本译文、OCR 结果和译图。新扫描完成后，文本按原文和字段定位匹配；图片按文件、容器、对象 ID 和原图哈希匹配，复制已校验的译图与识别／翻译状态到新工程。改变的原文或原图不套用旧结果。只有复用结果成功写入新工程后，才清理旧工程；扫描中止时旧结果仍在。

2.1 与 2.2 各自运行、中止、恢复和跳过。一键流程同时启动两部分；手动启动其中一部分后，也可在其运行中启动另一部分。停止或出错的一部分不会中止仍在处理的另一部分。界面分别显示各自状态与进度，生成补丁等待所需结果完成或明确跳过。

文本任务只合并文本条目，图片任务只合并图片结果。全工程保存与逐图检查点写入使用同一串行写入队列，避免覆盖另一任务的进度或同时操作临时保存文件。任务检查点保存两部分的状态；重开时从已保存的实际译文和图片状态恢复计数。
